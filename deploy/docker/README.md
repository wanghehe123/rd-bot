# Docker deployment layout

This directory holds the supported single-machine Docker deployment configuration.

| File | Purpose |
| --- | --- |
| `runtime.env.example` | Template for `runtime.env` (generated by `./scripts/rd-bot.sh up`; 0600; gitignored). |
| `application-docker.yaml` | Security overlay loaded via `SPRING_CONFIG_ADDITIONAL_LOCATION`: in-container listen address, re-disabled external intake, no public mutation token. |
| `migrate.sh` | Idempotent migration runner (checksum ledger `rd_schema_migrations`, single transaction per file). |

The Compose stack lives at the repository root in [`docker-compose.yml`](../docker-compose.yml).
See the root [README](../README.md) for the supported operation commands
(`./scripts/rd-bot.sh up / status / logs / restart / down / purge`).

## Layout facts

- The backend container listens on `0.0.0.0` inside the Compose network; the host
  publishes only `127.0.0.1:${RD_BOT_PORT:-18080}`.
- `/var/run/docker.sock` is mounted read-write into the `rd-bot` service only; the
  host socket group is injected with `group_add: [DOCKER_GID]` (no privileged mode).
- `${RD_BOT_WORKSPACE_ROOT}` is mounted at the SAME absolute path inside the
  backend container so the host Docker daemon can bind-mount task workspaces into
  Pi/QA agent containers.
- The egress network has a fixed, overridable name (`RD_BOT_EGRESS_NETWORK`);
  the backend is reachable as `rd-bot` on it for credential-relay traffic.
- Isolated acceptance stacks must override `COMPOSE_PROJECT_NAME` and
  `RD_BOT_EGRESS_NETWORK` with run-id-unique values; volumes are project-scoped
  automatically.
